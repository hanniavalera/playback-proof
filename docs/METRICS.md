# Metric definitions

A metric is a definition plus the place it is measured. These are the definitions every baseline, A/B report and readiness check in this
repository uses. They are implemented once, in `src/player/metrics.ts`, and exposed by `window.__qa.metrics()` ([`src/shared/qa.ts`](../src/shared/qa.ts)).
Changing a definition invalidates every committed baseline, so a change here must regenerate them in the same pull request.

| Metric                | Definition                                                                                                                                                                                                      | Why this way                                                                                                                          |
| --------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| **Startup time**      | Milliseconds from the `load-requested` event (just before `player.load()`) to the `firstframe` event: the first video frame presented (`requestVideoFrameCallback`; the `playing` event where the API is missing). | It is what a viewer waits for after pressing play. It excludes page load and the download of the player library, which a player team does not control per title. |
| Manifest time         | `load-requested` to `manifest-loaded`.                                                                                                                                                                          | Splits "slow origin / manifest" from "slow first segment" when startup regresses.                                                    |
| **Rebuffer event**    | A `buffering` episode (Shaka `buffering` true then false) that starts after `firstframe` and is not caused by the viewer's own seek (the seek window runs from `seeking` to the first `playing` after `seeked`). | A seek is allowed to buffer; an unprompted stall is the defect.                                                                       |
| **Rebuffer count**    | Number of rebuffer events.                                                                                                                                                                                      |                                                                                                                                       |
| **Rebuffer duration** | Sum of the rebuffer events' durations, ms.                                                                                                                                                                      |                                                                                                                                       |
| **Rebuffer ratio**    | rebuffer duration / (rebuffer duration + time in the playing state) since `firstframe`.                                                                                                                         | The standard streaming-quality ratio; comparable between sessions of different length.                                                |
| **Dropped frames**    | `video.getVideoPlaybackQuality().droppedVideoFrames` (and decoded = `totalVideoFrames`) at the end of the window; **dropped ratio** = dropped / decoded.                                                          | Available in all three engines. A CPU-throttled run shows it.                                                                         |
| **Effective fps**     | Frames presented (counted with `requestVideoFrameCallback`) divided by the media seconds that elapsed in a measurement window (`qa.measureFrames(mediaSeconds)`); content is 30 fps, so a healthy run reads about 30. | Dropped-frame counters can read zero while the compositor still skips; presentation is what the viewer sees. Measured over media time, not wall time, so a stall does not read as low fps. |
| **Bitrate switch**    | A change of the active video variant after the initial selection. Reason: `abr` (Shaka's adaptation), `manual` (`selectVariantByHeight`), or `start` (initial).                                                    | Counts quality changes; a flapping ABR shows as a high switch count.                                                                  |
| **Live latency**      | Distance from the playhead to the live edge, ms (`seekRange().end - currentTime`, in the player's clock, after Shaka's own latency correction). Reported as the current, maximum and (in readiness runs) p95 over the window. | The number a live-event owner is paged about.                                                                                         |
| **Stall recovery**    | From `buffering-start` to the next `playing`, during an injected origin stall.                                                                                                                                   |                                                                                                                                       |
| **Flake rate**        | Per test: runs in which the test failed and then passed on a retry, divided by the runs in which it executed. Failure rate: runs in which it failed after all retries, divided by the runs executed.               | A retried pass is not a pass; it is the cost the team pays for a test it cannot trust.                                               |

## Summaries

- Repeated runs report **median and p90** (and the run count). The mean hides the tail: a title that sometimes takes four times as long is what members complain about.
- Baselines are per environment (`detectEnvId()`), per profile (`chromium`, `chromium-cpu4x`, `firefox`, `webkit`) and per scenario.
- Regression rule (see ADR-004): a metric regresses when its median is worse than the baseline's by more than the relative threshold **and** the absolute floor,
  or when its p90 is worse by more than the (wider) p90 threshold. A first failure is re-measured with fresh runs and the build fails only if the regression reproduces.

## What the numbers do not claim

They are laboratory measurements on localhost with software decoding and synthetic content. They compare builds and configurations under identical
conditions. They are not production quality-of-experience numbers and are not comparable between environments.
